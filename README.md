# Сайт преподавателя Е. А. Вовк

Статический сайт Елены Александровны Вовк, преподавателя Ровеньковского технико-экономического колледжа: работы, материалы к занятиям, успехи студентов, достижения, новости, учебные игры и тесты по дисциплинам.

- Сайт: https://flyingsteps11.github.io/elena-vovk/ (GitHub Pages), запасной адрес — https://elena-vovk.netlify.app
- Редактор (Decap CMS): https://elena-vovk.netlify.app/admin/
- Справка редактора: [`admin/help.html`](admin/help.html) — открывается кнопкой «? Справка» в редакторе
- Справка для студентов: [`help.html`](help.html) — ссылка «Как пользоваться сайтом» в подвале

Этот файл — для того, кто поддерживает сайт технически. Редактору и студентам он не нужен.

## Как устроено

Обычные HTML, CSS и JavaScript без фреймворков и без зависимостей. Единственный шаг сборки — `node tools/build.mjs` (Node 22, только встроенные модули).

```
content/<раздел>/*.json   ← одна запись — один файл; их пишет редактор (Decap CMS)
        │
        ▼  node tools/build.mjs
data/<раздел>.json        ← записи раздела одним файлом; их читают страницы в браузере
works/<id>.html           ← страница каждой работы
news/<id>.html            ← страница каждой новости
games/<id>.html           ← страница каждой игры (5 видов)
tests/<id>.html           ← страница каждого теста
games.html, tests.html    ← списки игр и тестов вставляются между маркерами <!-- @games -->, <!-- @tests -->
*.html                    ← шапка и подвал из partials/ вставляются между <!-- @header --> и <!-- @footer -->
sitemap.xml
```

Сгенерированные файлы (`data/`, `works/`, `news/`, `games/`, `tests/`, вставки в страницах, `sitemap.xml`) лежат в репозитории. Их не правят руками: при следующей сборке всё перепишется.

### Что редактируется, а что нет

Через редактор меняются только разделы из `admin/config.yml`. Тексты главной страницы, меню, подвал, оформление и страница 404 — в коде.

## Хостинг: GitHub Pages (сайт) и Netlify (редактор и запасной адрес)

Каждый push в `main` и каждое сохранение в редакторе запускают две независимые сборки; через 1–2 минуты изменения на обоих адресах.

### GitHub Pages — основной адрес

- `.github/workflows/pages.yml`: `node tools/build.mjs`, затем в `_site/` копируются только публичные файлы (без `admin/`, `content/`, `tools/`, `partials/`) и публикуются на Pages. Включается один раз: Settings → Pages → Source: **GitHub Actions**.
- Сайт лежит в подпапке `/elena-vovk/`, поэтому все ссылки в коде относительные (`css/base.css`, а не `/css/base.css`); пути к загрузкам вида `/uploads/…` из редактора страницы превращают в относительные (`safeUrl`, `up`). В `404.html` при публикации `<base href="/">` заменяется на `<base href="/elena-vovk/">`.
- `/elena-vovk/admin/` на Pages — заглушка, которая переводит в редактор на Netlify с сохранением `#…_token=` из писем.
- Адрес сайта для canonical, og и sitemap — константа `SITE` в `tools/build.mjs` и `site_url` в `admin/config.yml`; в статических страницах он вписан в `<head>`.

### Netlify — редактор и запасной адрес

- Сборка: `node tools/build.mjs`, публикуется корень репозитория (`netlify.toml`).
- Заголовки: долгий кэш для `/fonts/*` и `/img/*`; `X-Robots-Tag: noindex` для `/admin/*`.
- Netlify отдаёт страницы без `.html` (`/tests` вместо `/tests.html`) — ссылки в коде всё равно пишутся с `.html`.
- `.github/workflows/build.yml` — ручной запуск сборки с коммитом сгенерированных файлов в репозиторий (только `workflow_dispatch`), на опубликованный сайт не влияет.

### Вход в редактор: Netlify Identity + Git Gateway

1. В проекте Netlify включён **Identity**, регистрация — **Invite only**.
2. Включён **Git Gateway**: через него редактор пишет коммиты в GitHub от имени сайта, редакторам не нужен аккаунт GitHub.
3. Редакторы приглашаются в Identity → Invite users. Подробно для владельца — раздел 15 справки редактора.
4. `index.html` перенаправляет ссылки из писем (`#invite_token=`, `#recovery_token=`, `#confirmation_token=`, `#email_change_token=`) в `/admin/`, где виджет Identity их обрабатывает.

Коммиты из редактора подписываются шаблонами из `admin/config.yml → backend.commit_messages` («Работы: добавлено «…»»).

## Локальный запуск

```bash
node tools/build.mjs
python -m http.server 8000
```

Затем http://localhost:8000. Страницы читают `data/*.json` через `fetch`, поэтому открывать файлы двойным щелчком (`file://`) нельзя — нужен локальный сервер. Редактор локально не войдёт (нужен Netlify Identity); для проверки формы можно временно скопировать `admin/` с `backend: { name: test-repo }`.

## Правила сборки, о которых стоит помнить

`tools/build.mjs` **молча пропускает** записи, которые не может показать: нет названия, адрес (`id`) не `^[a-z0-9-]+$`, `published: false`, а также неполные игры и тесты (меньше 3 шагов, меньше 2 корзин или 4 карточек, вопрос без верного ответа и т. п.). Адреса игр и тестов общие: при совпадении показывается первая по порядку видов. Полный список правил в понятных словах — раздел 13 справки редактора; **при изменении фильтров в сборке обновляйте этот раздел** (и поля в разделах 6–12 при изменении `admin/config.yml`).

## Игры и тесты

Все игры и тесты устроены одинаково:

1. Раздел в `admin/config.yml` (папка `content/<вид>/`).
2. Строка в `putData('games', …)` (или своя `putData`) в начале сборки.
3. В сборке: отбор и проверка записей → функция страницы (`quizPage`, `orderPage`, `sortPage`, `testPage`…) через общий `gameShell()` → запись страниц → карточка в каталоге → строка в sitemap.
4. Данные для игры лежат в странице в `<script type="application/json" id="cw-data">`; ответы закодированы `enc()` (UTF-8 → base64), движок декодирует `decodeURIComponent(escape(atob(…)))`. Это защита от подглядывания, а не от взлома.
5. Движок `js/<вид>.js` строит игру внутри своего блока (`.qz`, `.mt`, `.od`, `.sb`, `.ts`), результаты хранит только в `localStorage` (`cw:`, `qz:`, `mt:`, `od:`, `sb:`, `ts:` + id). Ничего не отправляется.
6. Стили — раздел в `css/games.css`, с вариантом для `max-width:760px`.

Новый вид игры удобнее всего делать по образцу «Разложи по корзинам» (`sortPage` в сборке, `js/sort.js`) и не забыть: исключить совпадение `id` с другими видами, добавить вид в обе справки.

Тесты дополнительно: банк вопросов и случайная выборка `count`, таймер `minutes` (дедлайн хранится в `ts:<id>:run`, поэтому перезагрузка его не сбрасывает), пороги оценок `five/four/three`, типы `one / many / text`; ответ с вводом сравнивается после нормализации (регистр, пробелы, ё→е, запятая→точка, `%`/«руб.» в конце).

## Обновление Decap CMS

Версия закреплена в `admin/index.html` вместе с хешем `integrity`. Чтобы обновить: поменять версию в адресе и пересчитать хеш:

```bash
curl -sL https://unpkg.com/decap-cms@<версия>/dist/decap-cms.js | openssl dgst -sha384 -binary | openssl base64 -A
```

После обновления проверить вход, сохранение записи и загрузку файла. Учтите: в Decap 3.17 нет `CMS.registerAdditionalLink`, поэтому кнопка «? Справка» в редакторе — обычная ссылка, которую добавляет `admin/index.html`.
